# Mutation Host Prototype

This .NET Framework 4.8 x64 library composes native SSIS loading, mutation previews, corpus fingerprints, checkpoint and validation callbacks, and staging for task renaming, bounded column resizing, and positioned Derived Column/Data Conversion insertion. The CLI exposes capability discovery, redacted previews, and apply through the MutationHost lifecycle. `NativePackageMutationValidator` runs native `Package.Validate` with `OfflineMode` enabled and restored afterward; validation does not connect to data sources or execute the package. `FileMutationCheckpointService` provides hash-verified checkpoint copies. A native Flat File fixture verifies successful CLI apply through checkpoint, save/reload, validation, and semantic verification.

## Composition Boundaries

- The host references Core, Inspectors, AI, Corpus, Mutations, and Ssis16. No portable project depends on the host. Deployment requires Windows x64, .NET Framework 4.8, and the installed SSIS 16 runtime; the library does not package the native runtime.
- `IMutationCheckpointService` is injected. Storage, compression, retention, restore layout, and protection of checkpoint contents belong to its implementation. A checkpoint must preserve the full DTSX artifact; returning a fingerprint or hash alone does not establish that restoration is possible.
- `INativeMutationValidator` is injected. Its implementation must explicitly define available checks and resource access and return safe diagnostic codes. Successful loading is not native validation, and a stub reporting success is not verification that the required validation occurred.
- `MutationHostResult` is a distinct lifecycle-evidence contract, not the two-field `MutationResult`. The existing `MutationContractSerializer` does not serialize it; a dedicated, versioned host-result serializer remains follow-up work.
- The host rebuilds the rename preview or checks the exact resize plan against the loaded native artifact, saves with native `SaveToXML`, and reloads the staged XML before validation and semantic verification. It depends on injected implementations to provide truthful checkpoint and validation evidence.

## Coordinated Column Resizing

`AnalyzeColumnResize(sourcePath, taskId, sourceComponentId, outputColumnId, destinationComponentId, proposedWidth, sampleRowLimit)` scans the data file configured on the selected native Flat File Source and reports rows scanned, maximum observed width, EOF/sample status, and a fixed diagnostic code. It returns no values, paths, or raw parser errors. Width is measured as UTF-16 code units for `DT_WSTR` and as bytes in the configured source code page for `DT_STR`. The scan is bounded to 1..10,000 rows; a partial sample cannot establish that unscanned rows fit.

`PreviewColumnResize(..., proposedWidth, quickAnalysis, acknowledgeDataLoss)` returns a source-hash-bound plan with current/proposed widths for every affected layer. The analysis is bound to the artifact hash, native selectors, proposed width, and analyzed source-file hash. A shrink requires successful analysis and explicit acknowledgement; the returned `DataLossConfirmationMessage` must be shown to the user before setting `acknowledgeDataLoss: true`. Even a complete current-file scan cannot predict future rows; sampled scans additionally warn that unscanned rows may be longer. A target below the maximum observed width is always refused. The data-file hash is rechecked before execution, and any change invalidates the plan. Execution uses `MutationHostRequest` with the resize plan and a distinct destination path.

Selectors are native IDs, not names. The supported topology is exactly one direct Flat File Source output connected to a Flat File Destination or OLE DB Destination input; types must be compatible `DT_STR` or `DT_WSTR`. Flat File metadata must be delimited, and width is bounded to 1..4000. The operation refuses no-op/mixed-direction plans, missing or mismatched analysis, observed truncation, changed source bytes/data/widths, unsupported branches, missing IDs, incompatible metadata, and existing destinations. Add/remove remain separate in-memory schema-edit operations.

The edit coordinates source file-manager, output and external metadata, the selected destination input and external metadata, and the destination file-manager width when present. After native save/reload and the validator callback, verification checks the exact resulting native signature and proposed widths. The signature ignores only the package-root `VersionGUID`, which SSIS regenerates during serialization. Corpus snapshots do not contain column widths, so this native signature is required in addition to the projected semantic checks. Tests independently assert that six intended width attributes change in either direction and that a neighboring column, selected input identity, and mapping are preserved.

This creates a separate DTSX copy; it never overwrites the source or issues physical database DDL. Resize lifecycle tests use injected checkpoint/validator doubles. CLI insertion apply uses the production file checkpoint and `NativePackageMutationValidator`, which runs `Package.Validate` offline. Native acceptance tests cover both successful publication of a valid Flat File fixture and refusal to publish packages with validation errors. Tests do not call package `Execute` or connect to a data source. Broad mutation authorization and journaling are not supplied.

## Designer Layout Utilities

`DesignerLayoutExtractor`, `DesignerLayoutService`, and `DesignerLayoutComparer` operate on `DesignerLayoutSnapshot` values and are separate from corpus, dependency, and generic mutation-contract models. The preservation comparer rejects changes to existing node positions, path endpoints, or routes while allowing added nodes and connections. Native component IDs are scoped to their owning data-flow task. The parser accepts bounded `DesignTimeProperties` XML with `NodeLayout` coordinates and optional edge/path route points; placement is deterministic, owner-scoped, avoids known nodes/routes, and refuses unknown positions instead of assuming `(0,0)`. `Normalize` is explicit and shifts only the selected owner canvas, including known route points.

The integration probe covers parser bounds/DTD refusal, placement-intent preview, comparison, native component/path extraction, and generation/reload of seven layout fixtures. SSDT-authored Control Flow positions pass for all seven; `TwoComponentHorizontal` also verifies Data Flow component positions and a curved path through native save/reload. MutationHost accepts source-hash-bound Derived Column and Data Conversion insertion plans, rebinds stable layout IDs to current native IDs, checkpoints and stages a separate artifact, reloads, validates, and verifies the expected insertion/layout. Versioned preview JSON omits expression text and transient numeric IDs. `FileMutationCheckpointService` provides hash-verified, non-overwriting checkpoint copies. CLI preview and apply routes are covered by native integration tests; apply uses offline `Package.Validate` and refuses publication on validation errors. The test-double lifecycle cases continue to verify successful save/reload/semantic publication. Data Conversion currently supports explicit `DT_WSTR`, `DT_STR`, integer, and floating-point output types. Use `--inspect-designer-fixtures <directory>` and `--verify-designer-fixtures <directory>` for additional SSDT-authored fixtures. Run `--designer-layout-probe` after building.

The host holds the source read-only from hashing/loading through checkpoint creation and publication. The stager requires a different destination, refuses an existing destination, and opens another source read lock while staging. Both original and reloaded native packages are disposed, including load failures. Source file sharing prevents normal Windows writes/deletion during the lifecycle; it is not a sandbox against privileged actors. A corpus fingerprint describes projected semantic state, not all omitted package content and not restoration data.

## Rename Coverage

`RenameCoveragePolicy` permits the explicit `coverage.task_properties_not_inspected` omission only when it belongs to a known executable. Those gaps remain visible, and corpus fingerprints retain `IsComplete: false`. This is rename-scoped verification, not certification of full task semantics or execution behavior. Unresolved SQL/expression references, metadata-read failures, unknown omissions, and invalid owner identities remain blocking.

The rename verifier permits the executable name and its companion data-flow name to change for the same native target ID; all other names/metadata, package identity, edge inventory, and coverage counts must match. The staged snapshot is rebuilt after the validator callback so callback-induced projected changes cannot evade this comparison. Native serialization methods are protected virtual hooks for focused save/reload failure injection; default implementations use native SSIS XML serialization/loading.

## Lifecycle Tests

Run `SsisAiRuntime.Ssis16IntegrationTests.exe --mutation-host-probe` after building. Twenty-six cases cover successful rename and positioned Derived Column/Data Conversion insertion save/reload/publication through validator doubles; stale names, missing/duplicate IDs, source hash changes, missing requirements, existing/concurrently created destinations, file-checkpoint overwrite refusal, checkpoint failures/hash mismatch, genuinely asynchronous checkpoint continuation, save/reload failures, validator errors, semantic mismatch, source locking, cancellation, nested and event-handler tasks, missing destination directories, incomplete coverage, offline native validation, and successful CLI apply. Originals are preserved and staging files removed. The production `FileMutationCheckpointService` creates hash-verified, non-overwriting copies. No package `Execute` or data-source connection occurs.

Run `SsisAiRuntime.Ssis16IntegrationTests.exe --column-resize-probe` for the 15-case resize lifecycle suite. It covers complete and sampled Quick Analysis, maximum observed length, shrink acknowledgement and observed-truncation refusal, stale analyzed-file refusal, native grow/shrink copy save/reload, selected-input identity and mapping retention, stale source/width refusal, topology/type refusal, checkpoint failure, validator mutation, destination preservation, and staging cleanup. Follow both required native gates in the repository build guide before merging changes to these slices.

Derived Column and bounded Data Conversion insertion are available through MutationHost APIs, with CLI capability discovery, redacted placement previews, and apply. AI apply returns a versioned lifecycle result and uses a separate destination plus caller-selected checkpoint directory. Broader edits, package generation, authorization/journaling, and SSIS-enabled CI enforcement remain follow-up work. No source-overwrite or general `set_property` command is provided.
